# ADR-0032：固定步输入记录与复现

日期：2026-11-15。状态：已实施。关联J09/J08/J13/O04。

网页和Unity SkillLab将外部操作统一提交给Config层的`SkillSimulation.Execute`，后者调用既有施放、输入、移动、打断等入口；Core不引入第二套施放规则或回放状态机。命令DTO独立于作者文档和战斗组件，按种类校验必填身份、坐标、整数和字段白名单。未知字段、重复属性、隐式字符串/小数转换及非法命令拒绝后不写入记录。

记录文件版本1保存独立的工程语义快照、预览种子、根技能、0.02秒步长、结束步数、有序`atStep/command`数组和末态`expectedState`。输入发生在当前逻辑步结束后、下一个逻辑步开始前，同一步的数组顺序即实际接收顺序；被冷却、能量或状态守卫拒绝的施放也保留。step/snapshot不属于输入，重放按相邻输入步差和结束步数补齐。暂停、倍速与渲染帧率不写成另一种战斗时间。

记录属于诊断文件，`expectedState`是结果参考，不是手工维护的第二套战斗配置。作者布局不影响复现，文件使用规范化布局，网页导入后恢复可编辑排版；不改变内容身份、发布槽文件或磁盘工程。直接用于单元测试的低层`Cast/Move`方法仍可调用，只有统一外部命令入口产生输入记录；两端用户输入均已使用该入口。

重放建立独立候选世界，用原随机源及命令入口运行，随后比较整个保留快照：属性、位置、实例、完整实体世代、来源节点、事件/轨迹顺序、技能和施法身份、资源与统计。浮点绝对容差0.0001，整数及字符串身份精确，最多显示32个差异路径；成功时所有值均参与比较。比较成功且Unity表现资源验证通过后才替换原世界，失败销毁候选并保留旧会话。当前协议用于当前运行规则的复现，不承诺不同未来Core版本之间结果不变。

网页导出/重放先暂停并冻结新命令，等待既有命令队列完成后捕获一致记录；候选校验期间若工程语义变化，则拒绝过期结果。复现响应通过项目自己的JSON编码器返回`projectJson`原文，避免System.Text.Json将Newtonsoft的JObject参数序列化为枚举结构。该边界曾在真实“复现后改种子”流程中暴露，已用HTTP回读再编译和浏览器修改/重建验证。

网页失焦或隐藏会暂停播放、取消保持、清空移动键和移动请求。帧预算最多接受0.2秒墙钟时间、每次20个固定步，超出时间丢弃；0.25倍速也保留不足一步的余量。Unity复现停在末态，不采集鼠标/失焦取消；F5重新载入发布内容并恢复进入复现前的自动推进选择。Editor提供`Combat/Skill Lab/Load Input Replay...`和`Save Input Replay...`菜单。

每条记录最多30000步、10000次输入。超过上限后预览可继续，但明确禁止导出不完整记录，要求重置。现有500条事件和4000个轨迹点容量继续生效，末态比较覆盖保留窗口，输入数组仍包含从初始世界开始的完整操作。实际验收见`docs/验证/2026-11-15-input-replay.md`。
