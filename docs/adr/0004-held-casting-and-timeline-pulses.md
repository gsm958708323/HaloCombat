# ADR-0004：引导施放、输入保持与 Timeline 周期触发

日期：2026-11-14。状态：实施中。

## 领域边界

引导是一次施放的持续过程，不能由浏览器反复发送“瞬发”来模拟。施放资格、启动扣费和冷却由 `SkillCastComp` 处理，时间与周期触发仍由 TimelinePlayer 推进；表现端仅发送按下、瞄准更新、松开、移动和中断输入。

## 决策

- `TimelinePayload` 增加可选重复间隔，0 表示单次；触发时间为 `Time + 序号 * Interval`。同一调度步跨越多个触发点时按时间、原数组顺序投递，定义不保存运行计数。
- 持续引导的 Timeline 可以无限长，但每次触发间隔至少 0.001 秒；有限引导使用独立的引导时长。不会预先创建无限数组。
- Timeline 每次推进前通过本次播放的资源预算函数取得可推进时间，每次触发前检查分段耗能；预算不足只推进已经付费的部分，然后结束。启动扣费成功才开始冷却；后续不足不退款，不开启第二次冷却。
- 引导耗能按逻辑秒扣除，受 Hitstop 冻结；启动费用与每秒消耗分开。有限连发可选择每段扣费，首段在接受施放时预付，之后在触发时扣费。
- 引导松开立即停止后续触发；已经生成的投射物依其自身生命周期继续运行。中断、死亡、卸载和明确重载清理剩余调度与移动意图。
- 引导期间通过现有 Locomotion 运动通道移动；方向/目标在每次触发时按当前输入重新解析，不改写只读定义。持续输入失焦或指针取消时必须释放。
- 蓄力仍属于完整清单，另批实现释放时序、倍率和提前释放契约；本决策不冒充已经完成蓄力。

## 验收

有限/持续引导、按住/松开、每秒扣费与不足、分段扣费、重复按下、冷却拒绝、小间隔跨步补发、移动中引导、打断/死亡/回收与跨实体不串状态。网页宿主和 Unity 使用同一模拟与输入，分别运行相关测试。
