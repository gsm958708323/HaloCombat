# ADR-0048 连招作者意图、规则范围与真实执行解释

日期：2026-11-16。状态：2026-11-17已实施。关联网页技能编辑器功能清单、连招编辑器设计说明。

## 问题

现有界面把整张运行输入表按输入令牌画图，混合空闲起手、局部接续、公共取消和验证示例。八条箭头可能只是三条共享规则，不表示八套连招或本次执行路线。隐藏节点只能缓解画面拥挤，不能说明作者意图和改动影响。新建连线自动提高优先级还会静默覆盖旧规则。

## 决策

1. 作者操作分为起手绑定、动作接续、公共取消，仍编辑唯一的 runtime.combos。可选 purpose 明确用途，不参与战斗匹配、技能装配或权限过滤。未包含该字段的公开JSON保留原行为：空前置可确定为空闲入口，其余显示“未标用途”，不根据技能名称、输入名或前置数量猜业务。
2. 可选 editor.comboViews 仅保存名称、根技能、规则ID和节点位置。视图支持共享同一规则，修改显示影响范围；删除视图不删规则。引用随规则删除、用途变化、技能改名/删除和工程合并同步。运行导出删除作者视图，不丢运行规则的用途。
3. 动作图按已有引用生成，支持跨输入、分支、循环；公共取消集中编辑。前置集合是OR，所需正向Tag是AND。对图的筛选、折叠、布局和命名不影响全表查找。
4. 编辑图保持稳定，运行状态只改变覆盖高亮。本次路径来自真实成功施放，重复技能保留每次出现。规则选中、施放失败和成功分开；同一次查找的冷却或资源失败不回退其他候选；缓冲输入在后续逻辑步仍按当时状态重新求值。
5. 新增及修改匹配字段时，针对全表检查相同输入和重叠前置。正向Tag集合可能同时满足，不能据不同Tag断言互斥。作者明确确认优先关系；平级歧义仍由协议编译拒绝。新增线先创建草稿，不直接改变战斗行为。
6. 预览诊断可选开启，记录实际查找前的条件和施放后的结果，按状态变化发结构化事件；使用独立64条有界诊断通道与独立序号，回放结果明确排除纯显示诊断，不开启全量输入录制、不逐帧记录重复失败，不由网页重跑匹配器冒充真实结果。

## 边界和代价

现有运行时不记“来自哪个连招方案或第几段”。同一技能在同一状态、同一输入下无法因不同编辑视图区分后续。此类需求必须另行引入明确领域上下文，不能靠复制图节点实现。当前不新增流程状态机。

purpose 是公开JSON的可选补充；身份、输入、前置、条件、优先级及目标语义不变。正式工程补全用途和两个项目自有功能视图；不改用户工作工程、F6/F7或旧发布包。其他工程无需重建规则，按需标注用途和保存视图。

## 验收

覆盖起手、跨输入分支、集合取消、循环、条件冲突、共享视图影响、身份操作、保存/导出/导入/合并；用同一JSON验证宿主与Unity的输入匹配、窗口等待、命中确认、资源拒绝和成功路径。验收见 docs/验证/2026-11-17-combo-authoring.md。
