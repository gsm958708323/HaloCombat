# ADR-0052 全工程连招图与运行高亮

日期 2026-11-22。浏览器在 1280×800 和 1780×1050 下均可用鼠标选中全部 38 条接续线，连线未穿过无关卡面。部分交汇处的点击区域重叠，每条线均有可独立选择的线段。二段第 45 帧和 G1 第 8 帧均只高亮实际接续的爆弹卡。规则 JSON 的重复键被拒绝，优先级从 5 改为 6 后可撤销回 5。Unity MCP 在 Arena Play Mode 验证了正式输入，同一 Play Mode 中的独立 `SkillSimulation` 读取网页导出的完整原件后运行到 G2，Console Error 为 0。

## 背景

策划需要从同一张图查看工程里的主干、派生和回环，并在预览时看清角色正在播放哪一段。按技能展开和手工视图会把相关接续分散在不同入口，同一技能也会因视图范围不同而显示不同的边。

## 决策

- 画布从 `runtime.combos` 投影所有 `preSkills` 非空的规则。每条规则的每个真实前置生成一条边，连到来源附近的 `toSkill` 卡片，按规则 ID 关联原 JSON 对象。技能可在不同分支显示引用卡，已展开的技能在其他分支以引用卡结束，局部回环指回当前路径中的已有卡片。总览根节点和虚线仅用于组织画布。
- 图选中状态只驱动右侧检查与编辑。同一技能的引用卡共享原 Timeline 和关联规则 JSON。Timeline 按内联、共享、自动时序各自的定义写回。规则 JSON 经过现有工程编译校验，成功修改接入草稿和撤销。空前置规则仍由同一张表提供起手匹配，其编辑入口是工程运行配置。
- 预览用独立会话运行整个候选工程，实际逻辑输入交给 C# 战斗核。成功接续时，用 C# 记录的 `rule` 和 `fromSkill` 定位边与目标卡，用 `castId` 对应当前施放。角色回到空闲时清除高亮。选择节点只更新编辑对象。选点、暂停或单步均沿用当前预览会话。

## 协议与取舍

`editor.comboViews` 和 `editor.comboPositions` 继续作为公开 JSON 的可选作者元数据。全局图直接从规则表计算布局。规则匹配、草稿保存和单技能槽的发布契约沿用现有实现。[ADR-0048](0048-combo-authoring-intent-and-runtime-explanation.md) 记录旧工作台的决策。

分支内的引用卡缩短公共取消和多前置规则的连线。完整后续集中在该技能的展开处，每条有效接续仍可在图中查看。
