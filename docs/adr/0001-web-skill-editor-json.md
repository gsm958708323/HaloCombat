# ADR-0001：网页技能编辑器与 JSON 唯一内容源

日期：2026-11-14。

状态：方向已由用户明确决定；细化协议与运行时实现尚未完成。本记录不是功能已交付的证明。

## 决策来源

用户在本次会话明确要求：1:1 复刻参考视频中的技能编辑器，使用网页实现，最终交付 JSON，项目也使用 JSON，不再兼容 SO 配置。

这项新要求优先于此前的 Unity Editor 技能工作台提案及仓库文件中关于 SO 为唯一作者内容源的旧约束。保留未被这项决定改变的纯 C# 核心、组件职责、Timeline/Clip/Payload、ComboEntry、结算和生命周期规则。

## 已决定的方向

1. 作者工具是独立网页技能编辑器，按 BV1cC4J6fEac 的可见界面、操作与运行预览对照验收。
2. 战斗作者配置和游戏加载配置使用 JSON；最终发布链路不依赖 ScriptableObject。
3. 正式内容从 JSON 校验并转换为纯 C# 运行时快照。删除现有 SO 内容加载、Bake、回退与双写路径，不建立长期兼容层。
4. 当前内容一次性迁移并保留稳定身份与表现绑定；迁移辅助工具不进入正常运行路径，迁移结束后删除。
5. Prefab、材质、动画、纹理、音频等 Unity 原生资源继续使用。它们与 JSON 之间通过明确的资源身份绑定；承载战斗配置的 SO 和现有 View/Cue 配置 SO 应纳入替换审计，不能保留为隐蔽内容来源。
6. 网页运行预览、导出的 JSON 和 Unity 实际运行必须验证一致；画面演示不能代替真实执行或只把新字段放进文件。
7. 此前提案中的三个主要编辑视图不作为本次 1:1 界面要求；主要作者体验按照视频的目标选择、施放规则、效果传递、投射物行为、效果结算与技能事件节点组织。
8. 用户随后明确排除装备、计算公式、地图、冒险四个独立页面及导航入口；保留技能预览中的目标/障碍布置与实际伤害计算。

## 明确的影响

- 内容源与协议：SO 引用切换为 JSON 中的类型化身份与引用；增加格式版本、错误路径、引用与递归校验。
- Config：替换 ScriptableObject 作者类与 Bake 入口；协议 DTO 与 Core 运行时定义分别维护，转换逻辑独立。
- Unity：替换 Bootstrap、Rules、相机参数、角色、Cue/View 等配置消费点，清理旧场景对配置 SO 的引用；资源加载方式须在细化设计中明确。
- Core：可复用现有纯 C# 组件与效果；冷却接入、能量/蓄力/引导、链式弹体、分裂、判定形状等新机制须逐项定义参数和生命周期后实施。
- CLI/测试：增加使用正式 JSON 的验收路径；原代码 Demo 仅可作为独立示例或测试样例，不成为正式配置缺失时的回退。
- 文档与规则：实施时同步更新 AGENTS 与 README 中已被取代的 SO 配置说明；在实现完成前，不把 JSON 路径写成当前代码已存在。

## 尚未决定的实现细节

- 网页预览采取同源 C# 宿主、可复用编译产物或独立实现；无论采用哪种方式，必须覆盖相同场景和事件序列的对照验收。
- JSON 精确字段、模块枚举、资源映射与发布载入方式。
- 视频只露出菜单的能力、原工具未公开的默认值与边界语义。
- 四个被排除页面不再作为参考缺口或待实现项。

## 验证要求

网页编辑、保存、导入、导出和预览都必须实际工作。所有已开放节点要能导出并由项目执行；未知类型/字段按协议拒绝并定位，不能悄悄跳过。发布后加载新的完整快照，不修改正在执行的旧定义。

涉及 Core 的实现运行 `dotnet build Combat.csproj` 与 `regress`；Unity 代码、资产或场景变更运行编译及相关 EditMode/PlayMode，并确认旧配置引用已清理且 JSON 文件可从磁盘加载。视觉与交互对照、可执行 JSON、运行结果和旧路径删除分别提供证据。
