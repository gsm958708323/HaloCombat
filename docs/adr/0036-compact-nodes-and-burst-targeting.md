# ADR-0036：紧凑节点、有效摘要与有限连发

日期：2026-11-15。状态：已实施。关联UI-002、E02、D02/D03/D06、I01–I06。

默认节点先展示视频对应的主要参数，扩展资源/反馈/动作参数放入“更多参数”，穿透/连锁/同目标规则收在“投射物行为”。分组只是视图，不复制、删除或改写参数；所有适用字段恰好分到一组。未使用的额外事件可折叠，已连接端口始终显示；展开/收起后更新端口几何，连线身份/顺序和世界不会改变。布局生成按默认展开内容估算，作者已有位置原样保留。

施放增加明确的`burst`布尔覆盖。未提供时以count>1派生，保持已有JSON语义；显式false只执行一次而保留配置的次数/间隔/逐段支付，true使用保存次数，没有次数时默认3。网页开启单次技能时初始设3，关闭后再次开启恢复原次数。channel/charge不使用有限连发；显式Timeline和即时operation拒绝自动burst字段，不能同时维护两套时序。没有新增SO或旧配置兼容路径。

核对死亡射击发现原实现对瞬发连发只在施放时抽取一次随机方向，后续沿用。现在随机方向和随机目标在每个实际触发点重新选择；开始施放只做不消费随机数的可行性校验。Timeline按原时间顺序到点后，先不消费随机数地检查目标资格，再检查支付，成功才抽取本次方向/目标并投递。缺目标、未支付、打断后的未执行分段均不消耗未来随机序列。普通指定点/方向保持施放时锁定，channel继续按每次触发解析，charge在有效释放时解析一次。

该流程仍使用SkillCastComp/SkillTargeting/TimelinePlayer和World.Random。目标查询按当前存活敌方/范围和完整EntityId，不用过期实体索引；两个同一步小间隔触发仍各自执行/抽取。随机校验与采样共用一个解析入口的显式sample参数，不另建效果或浏览器随机模拟。

摘要现在从只读作者定义生成独立视图行：沿当前cast连线、明确顺序、显式/共享Timeline入口和共享弹体/区域引用读取。禁用分支与断开的草稿效果不参与有效摘要，重复显式引用显示引用数，循环与缺定义保留明确警告。共享定义不冒用调用者的多发参数；Buff行读取同一份定义的周期/持续信息。输出行只包含字符串属性和视图身份，不向组件共享可变作者节点。摘要分类按实际事件分支，并生成可读施放/选敌/传递/结算描述。

新增交付模板`death-shot`：“死亡射击 · 二十发”，20次、0.04秒间隔、每次独立随机方向。可在网页新建、调参、预览、下载、导入与Unity运行；模板身份和弹体运行身份独立分配，不覆盖用户工程。

验证包括前端71/71、相关EditMode84/84、相关PlayMode25/25，追加模板后相关10项完成无失败；实际网页开关20→1→20、保留0.04间隔、展开不重建世界、新建模板，以及网页实际下载文件45步/20方向/4377值与Unity一致。UI-002/E02本批关闭，视频的完整行为菜单、直接布置/复位及最终视觉/操作验收继续，详见独立验收记录。
