# ADR-0003：网页发布与 Unity 技能试验槽

日期：2026-11-14。状态：实施中，延续 ADR-0001/0002。

## 问题与边界

首轮网页发布只写工程文件，Unity 没有消费点。若为 Unity 再写一份预览世界，会让资源、目标、伤害和事件统计逐渐分歧。

## 决策

- 将现有宿主中的试验世界、Actor 工厂和只读快照移入 `Combat.Config/Json`，成为不依赖 Unity 的 `SkillSimulation`。网页宿主和 Unity 薄适配器调用同一模拟；Core 保留战斗结算职责。
- F6/F7 发布文件分别为 `Assets/StreamingAssets/Combat/f6.json`、`f7.json`。发布包明确包含协议版本、选中的技能身份、内容修订号和完整工程；修订号由规范化内容与技能身份计算，读入时验证。
- 网页发布当前选中技能。写入前完整校验，使用同目录临时文件原子替换；写入成功只承诺文件可加载，不声称游戏已经重载。
- Unity `SkillLab` 场景提供 F6/F7 试验槽，F5 明确重载两份磁盘发布包并重建世界；首次施放尚未载入时也会载入一次。两槽选中图合并为一个目录，共用施法者、资源和冷却，普通按键不会重置世界；鼠标施放上次选中槽。所有输入继续经过 `SkillCastComp`。
- 两槽必须来自同一工程。相同技能身份的不同版本拒绝混用，跨技能运行 ID 冲突交给统一编译器检查。试验场初始布置采用 F6 的场景，只有 F7 时使用 F7；这是试验场规则，不是未来正式关卡的内容加载契约。
- 仅完整构建成功才替换当前会话；失败保留当前有效世界并展示文件与字段错误。不存在 SO 或代码内容回退，已存在弹体不会被新定义原地改写。
- Unity 表现只消费模拟快照，不通过 Collider/Transform 反写战斗世界。

## 范围与后续

本批完成发布到 Unity 试验场的闭环，不等于 N01–N10 的既有游戏内容迁移。旧 SO 入口仍须在迁移批次删除。发布包暂时携带编辑布局；L04 的裁剪运行包、更多节点及正式角色槽位接入继续按完整功能清单推进。

## 验收

宿主与 Unity 使用同一文件、种子、输入和步数，对照出弹、命中、伤害与资源；验证选中技能映射、非法发布、坏版本/修订号、失败重载保留旧世界及成功重载清理。运行浏览器发布、Unity 编译、EditMode/PlayMode、Core regress，并记录各自证据。
