# ADR-0014 工程编辑、引用事务与保存快照

日期：2026-11-14。状态：已实施并验证。关联：B01、B03–B09、C01、C03、C06–C07、L03、L05、L09、L11。

## 问题与边界

编辑工程保存作者正在工作的状态，运行内容只接受可以执行的定义。此前将磁盘保存等同于完整战斗编译，会使断开连线、空工程等正常编辑中间态无法保存。拖动逐帧进入历史、异步保存误标最新内容、ID 改动遗漏共享引用，也会损坏作者的工作。

网页负责工程操作、选择与编辑历史；C# 继续负责协议结构、引用和实际运行语义。Core 不引用网页模型。技能、Buff 和召唤蓝图身份各自有独立命名空间，显示名和位置不作为身份。

## 决定

1. 工程操作使用不可变转换。改名保持 runtimeId，按字段类型同步所有技能/Buff 图和蓝图中的引用，包括禁用节点保留的引用。复制分配技能/定义/节点/边的新身份，共享 Buff 与蓝图仍保持共享；删除先展示引用和真实磁盘发布槽影响，有引用时必须先更换引用或取消。
2. 历史保存完整工程快照，一次字段编辑或拖动是一条事务；技能/Buff 切换和画布移动属于编辑元数据，不单独进入撤销栈。新建、复制、删除、批量节点/连线、参数和布局都可恢复。
3. `editor` 是可选的工程元数据，只保存选择与每张图的视口。C# 校验其有限坐标、缩放范围、图身份和唯一性。预览语义键忽略该元数据和节点位置，发布闭包移除编辑状态并规范化节点位置，布局改变不产生新的运行版本。
4. 工程结构校验与战斗编译分开。保存允许空工程、断开连线等草稿，但拒绝未知字段/节点类型、重复身份、无效结构、悬空端点和已选中的缺失共享引用。预览、配置应用与发布仍必须通过完整编译，不以草稿为运行回退。
5. 显式手动保存。浏览器保存捕获不可变快照，并使用磁盘 ETag 做条件写入；保存中产生的新编辑继续显示未保存。宿主串行检查版本并原子替换文件，冲突和写盘失败保留编辑并显示原因。刷新恢复最近磁盘保存，离开有改动的页面由浏览器提示。
6. 已发布 F6/F7 是独立且不可变的运行快照。编辑删除或 ID 改名不偷偷重写发布文件；操作前读取两槽的技能/Buff/蓝图闭包并展示影响，更新内容需要明确重新发布。
7. 节点剪贴板保存选中子图和内部连线，粘贴重分配身份、保留顺序与共享引用；跨技能/Buff 图遵守根节点限制。连线的显式 order 决定执行顺序，排版和数组顺序不能修改它。
8. 工程的引用管理包含禁用节点和隐藏字段；运行编译只解析生效节点及当前模式的引用。发布闭包因此可以裁掉禁用分支使用的蓝图/Buff，而保留作者图中的禁用节点；运行结构校验不能反过来要求这些无效依赖重新进入闭包。

## 验收

纯工程转换验证覆盖类型化改名/冲突、禁用引用、复制身份、删除引用、子图粘贴、顺序、历史分组和保存竞争。C# 验证空/草稿持久化与严格运行拒绝、元数据往返、布局不改变发布版本、条件写入及坏输入不覆盖文件。浏览器实测跨图视口、重命名与引用同步、复制/删除/撤销、节点复制粘贴和保存恢复。最终继续使用 Unity MCP 验证共享 JSON 编译和 SkillLab 场景。

本决策不表示正式 Arena JSON 迁移、完整视觉还原或其余节点已经完成；范围仍以完整清单为准。
