# ADR-0018 可破坏物与死亡连锁

日期：2026-11-15。状态：已实施。关联H06/N02、ENG-003。验收见`docs/验证/2026-11-15-constructs.md`。

依据本地历史fae7872：木桶为中立可受伤实体，出生在施法者前方0.55米、HP5、半径0.25；每5秒自伤1，非同组物体伤害封顶1。死亡半径2.2，敌人按拥有者当前Atk×0.15/暴击.05/倍率1.8结算；附近木桶通过9999伤害连爆，爆一次即回收。手动回收与卸载不是死亡爆炸。

新增construct节点描述可破坏物的生命、净空、阵营、受伤上限、周期自伤、组、视图、数量/上限、出生和死亡/移除效果。定义进入ConstructCatalog，运行态仅在ConstructComp；网页与正式RuntimeActorFactory使用相同组件。IncomingDamagePolicyComp是当前实际需要的目标受伤策略入口，限制在最终伤害进入护盾/HP之前；同组可破坏物的伤害绕过该物体上限。

死亡端口组合现有范围投递/伤害/Cue节点与独立construct-chain节点；链爆只选择指定组的可破坏物，普通范围投递可用明确阵营mask。区域查询不强加视线，保持原木桶隔墙范围规则。每个死亡只处理一次，通过World内FIFO死亡队列展开，避免大规模链爆递归堆栈；一次波次上限256并记录拒绝，世界/来源存活上限独立。顺序为当前物体死亡效果，排队的邻居随后按实际实体查询次序处理，不声称与历史递归回调事件顺序完全相同。

耗尽死亡波预算后只回收并发布DeathWaveLimit，不再执行业务death/removed回调，防止回调继续造物导致无限波次。该拒绝是显式运行事件；普通移除与正常死亡不受此规则影响。

死亡处理会嵌套发布伤害、生命周期和表现事件，EventBus此前复用一份可变快照，会丢掉外层剩余监听。现在每次分发使用独立快照；回调内订阅/退订只影响后续发布，嵌套发布也遵守当前监听表。实际物体死亡与独立嵌套事件测试覆盖该约束。

出生先设置位置/属性/Owner再PublishSpawn。拥有者关系保存完整EntityId，爆炸读取仍有效拥有者当前攻击；Owner已回收时使用0攻击，不能借复用索引的新角色。cleanupWithOwner可显式选择，历史木桶取false；卸载始终静默释放，不补播死亡/移除效果。普通移除只执行removed，死亡执行death后removed。

本批保留木桶生命/周期/范围/攻击系数和真实归属，提供具名barrel/crate视图。原爆炸的TargetHitstop=3和EvHurt级别反馈暂未映入当前正式内容：现有全局Hitstop会冻结拥有者及所有物体，不能假作目标独立顿帧；原资源/动画、角色成长与其余历史技能继续独立迁移。差异关联ENG-003，在N02/N03完整验收前实现并删除该缺口记录。

后续状态：ADR-0019已实现独立ActorTime、伤害来源/目标帧数和EvHurt，正式木桶目标3帧/Heavy反馈已验证，ENG-003于2026-11-15关闭；本ADR保留以上阶段边界作为历史上下文。原资源/动画仍需N08验收。
