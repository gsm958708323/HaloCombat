# ADR-0028：实体外观资源与 Cue 锚点

- 日期：2026-11-15
- 状态：已采纳，2026-11-15完成本节点验收
- 关联：N08、M06；历史fae7872的BuffArenaViews/Cues和角色锚点。

## 边界

角色动作与运行实体共享只读资源目录，但kind明确区分actor/body。Actor要求原Animator/状态；body只允许渲染、粒子和Transform，不携带角色Animator、碰撞或玩法脚本。Projectile/AoE/Construct通过view键引用，定义编译时验证，生成事件将实际资源键交给现有ViewRegistry。外观、粒子、旋转不能成为玩法的第二时钟；随ActorTime和真实AoE半径比例采样。

Cue资源保持独立，角色锚点从旧脚本提取成JSON路径/局部偏移。具名循环和单次事件可附到Body/Head/Muzzle，循环仍按完整EntityId/CastId清理。源Prefab、模型、贴图、材质GUID保留，Unity材质转换为当前URP；不引入旧SO或旧表现管理器。

SkillLab从同一发布会话读取外观目录，先验证Unity资源再替换世界；快照携带view/yaw/viewScale供场景显示。网页仍是逻辑二维示意，Unity验证实际Prefab和材质。发布与加载版本、实际参数必须在场景里核对，不能仅以HTTP写入成功作验收。

## 已知资源边界

历史提交只有音效键，无AudioClip文件；本节点不合成并冒充原音频。音频缺口保留，后续若提供原文件，可沿既有sound资源契约绑定。

## 发布修订与两槽一致性

发布包的完整性检查使用文件内原始project JSON，而非先转float DTO后再序列化。.NET与Unity Mono对同一个float会输出2.9133646/2.91336465，原校验会错误拒绝用户含随机布置坐标的文件。语义编译和未知字段校验继续完整执行，修改载荷仍拒绝；不增加两套运行配置或旧SO兼容。

共享定义冲突仍拒绝加载并保留当前世界。网页单槽发布后检查磁盘组合，显示可操作的冲突提示；“同步两槽”保留现有两个技能根，从当前工程重建闭包并在写入前整体校验。游戏仅在F5/Reload处替换会话，不在正在运行的实例上热改参数。SkillLab显示各槽根/修订和磁盘待载入状态。
